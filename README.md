# Media Server

Self-hosted media stack: Jellyfin for playback, the *arr suite for library
management, Prowlarr for indexers, and an opt-in VPN-gated download half.

Runs on **rootful Podman** under **Bazzite** (Fedora Atomic), with **NVENC**
hardware transcoding on an NVIDIA GPU.

## Services

| Service    | Port | Purpose                                    |
|------------|------|--------------------------------------------|
| jellyfin   | 8096 | Media server / playback (NVENC transcode)  |
| jellyseerr | 5055 | Request portal                             |
| prowlarr   | 9696 | Indexer manager — syncs to every *arr      |
| radarr     | 7878 | Movies                                     |
| sonarr     | 8989 | TV                                         |
| bazarr     | 6767 | Subtitles                                  |
| gluetun    | —    | VPN tunnel — **opt-in**, `--profile download` |
| qbittorrent| 8080 | Torrents — **opt-in**, published via gluetun  |

`gluetun` and `qbittorrent` do **not** start on a plain `up -d`. They require
`--profile download` and a configured VPN, by design (see *Download half*).

## Prerequisites

### 1. SELinux labels on the bind-mount sources

Fedora Atomic runs SELinux in **enforcing** mode. Host directories bind-mounted
into containers are `unlabeled_t` by default, and every service will crash on
startup with `Permission denied` writing `/config` — while the published port
still appears to LISTEN, because Podman's forwarder outlives the dead process.

Label the sources and make it persistent:

```bash
sudo chcon -R -t container_file_t /var/mnt/data/{media,torrents} \
                                  /var/home/$USER/appdata

# Persist across a filesystem relabel.
# NOTE: /var/mnt has an equivalency rule to /mnt — the fcontext spec must be
# written as /mnt/data, not /var/mnt/data, or semanage rejects it.
sudo semanage fcontext -a -t container_file_t "/mnt/data(/.*)?"
sudo semanage fcontext -a -t container_file_t "/var/home/$USER/appdata(/.*)?"
matchpathcon /var/mnt/data/media   # should report container_file_t
```

The compose file deliberately does **not** use `:z` / `:Z` volume suffixes.
Podman would relabel recursively at container start, which on a multi-terabyte
media volume is a needless full-tree walk on every `up`.

### 2. NVIDIA CDI device

Jellyfin claims the GPU via `devices: [nvidia.com/gpu=all]`, which needs a CDI
spec generated by the NVIDIA Container Toolkit:

```bash
sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
sudo podman run --rm --device nvidia.com/gpu=all \
  docker.io/nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

Verify NVENC end to end before trusting playback — a real encode, not just
device visibility:

```bash
sudo podman run --rm --device nvidia.com/gpu=all \
  -e NVIDIA_DRIVER_CAPABILITIES=compute,video,utility \
  --entrypoint /usr/lib/jellyfin-ffmpeg/ffmpeg \
  lscr.io/linuxserver/jellyfin:10.10.3 \
  -f lavfi -i testsrc=duration=5:size=1920x1080:rate=30 \
  -c:v h264_nvenc -preset p4 -f null -
```

Because `h264_nvenc` is requested explicitly, ffmpeg errors out rather than
silently falling back to CPU — so a clean exit means the GPU really encoded.

**Rootful is required.** NVENC is unavailable to rootless Podman on this host
(NVML reports `Insufficient Permissions` even with `no-cgroups = true`).

### 3. Environment

Copy `.env.example` to `.env` and set the paths:

```
DATA=/var/mnt/data                 # parent of media/ and torrents/
APPDATA=/var/home/<user>/appdata   # service configs, on SSD
TRANSCODE=.../jellyfin-transcodes  # transcode scratch — keep off the HDD
```

## Running

`podman-compose` installed via Homebrew is not on `sudo`'s PATH; invoke it by
absolute path or the command silently appears to be missing:

```bash
cd media-server
sudo /home/linuxbrew/.linuxbrew/bin/podman-compose up -d      # 6 services
sudo /home/linuxbrew/.linuxbrew/bin/podman-compose ps
sudo /home/linuxbrew/.linuxbrew/bin/podman-compose logs -f jellyfin
```

With the download half, once a VPN is configured in `.env`:

```bash
sudo /home/linuxbrew/.linuxbrew/bin/podman-compose --profile download up -d
```

## Storage layout

One `/data` mount is shared by every *arr and the download client, so imports
are **hardlinks** rather than full copies. This only works because the torrent
and media trees live on the same filesystem:

```
/var/mnt/data/
├── media/          # movies, tv, music, books — Jellyfin mounts this read-only
└── torrents/       # download target, same filesystem => hardlink imports
```

Split mounts (`/movies`, `/downloads` as separate volumes) break hardlinking and
make every import a full-size copy. That is the single most common misconfiguration
of this stack.

## Download half

`gluetun` owns the network namespace; qBittorrent joins it with
`network_mode: service:gluetun`. The killswitch is structural rather than a
setting: if the tunnel container stops, the client has no route out at all.
qBittorrent's WebUI is therefore published on **gluetun**, not on qBittorrent.

This replaces an earlier arrangement that set `VPN_ENABLED=yes` on
`linuxserver/qbittorrent`, an image with no VPN support — the variables were
ignored and torrent traffic left over the bare WAN IP with no visible symptom.

A VPN provider with **port forwarding** is required for healthy seeding.
Mullvad removed port forwarding in 2023.

## Gotchas

- **Podman requires fully-qualified image names.** `qmcgaw/gluetun` fails;
  `docker.io/qmcgaw/gluetun` works. Docker silently prepends the registry.
- **No spaces around `=` in compose env values.** `TZ = America/Costa_Rica`
  parses the key as `TZ ` and the value as ` America/Costa_Rica`. An earlier
  revision had 11 such lines, so TZ was never set in any service and Jellyfin
  never received its PUID.
- **`version:` is obsolete** in Compose v2 and is omitted here.
- **A listening port does not mean a healthy service.** Check
  `podman logs <name>`, not `ss -ltn`.

## Current state (as configured 2026-07-31)

The sections above describe the compose design. This section describes what is
actually running and how to reach it. Full session history is in
`dkos/.context/sessions/session_2026-07-31_media-stack-buildout.ccc.md`; planned

### Access

Every service is routed by Traefik on the tailnet. CoreDNS answers `*.dk.internal`
tailnet-only and refuses everything else, so these names do **not** resolve on the
LAN.

| Service | URL |
|---|---|
| Jellyfin | `jellyfin.dk.internal` — and `http://192.168.100.114:8096` for LAN devices such as the TV |
| Jellyseerr | `jellyseerr.dk.internal` |
| Radarr / Sonarr / Prowlarr / Bazarr | `<name>.dk.internal` |
| qBittorrent | `qbittorrent.dk.internal`, or `http://gruff:8090` |
| Homepage | `home.dk.internal` |

**Traefik routes live in `projects/infra/config/traefik/dynamic/`.** A second
directory exists at `appdata/traefik/dynamic/` — it is a stale leftover that
nothing reads. Editing it fails silently.

### Library layout

```
/var/mnt/data/
├── media/{movies,tv,music,books}   ← Jellyfin libraries, Radarr/Sonarr roots
└── torrents/{movies,tv,music,books} ← qBittorrent categories
```

Both trees are on the same filesystem (device 62) so *arr imports **hardlink**
instead of copying. A downloaded film therefore occupies its size once while
being simultaneously seedable and playable. Removing a torrent drops one
directory entry; the data survives via the library's entry and is freed only
when the last link goes.

Do not split these onto separate mounts — that silently reverts to full copies.

### Download half

Gluetun holds a ProtonVPN WireGuard tunnel; qBittorrent shares its network
namespace and has no network stack of its own. `PORT_FORWARD_ONLY=on` restricts
server selection to port-forward-capable servers, which on ProtonVPN are the P2P
ones.

The forwarded port is dynamic. Gluetun acquires it via NAT-PMP and runs
`/gluetun/update-qbt-port.sh`, which pushes it into qBittorrent's API — so the
port self-heals on reconnect with no manual step.

Three independent layers prevent a leak: the shared namespace, qBittorrent bound
to `tun0`, and gluetun's firewall. Verify isolation at any time by comparing:

```bash
podman exec gluetun wget -qO- https://api.ipify.org   # tunnel exit
curl -s https://api.ipify.org                          # gruff's own address
```

These must differ.

### Users

Jellyfin has no in-session profile switching. `bajura` and `fabi` are visible as
login tiles with no passwords, so switching is one tap; `kai` is the admin,
holds a password, and is hidden from the login screen. Both non-admin users have
REQUEST + AUTO_APPROVE in Jellyseerr, so requests reach Radarr/Sonarr with no
approval step.

Separate users are deliberate: watch history must stay two distinguishable
streams for any future recommender to be worth having.

### Subtitles

The Bazarr language profile is `en` + `ea` (**Spanish Latino**), not `es`.
Generic `es` resolves to Spain's variant on most providers.

Providers are limited to credential-free ones, which excludes OpenSubtitles.com
and materially limits Latin American coverage — see MS-3 in the roadmap.
`podnapisi` was removed on 2026-07-31: the site no longer resolves from anywhere.

### Operational gotchas

- `podman restart` intermittently fails with `conmon exited prematurely`, leaving
  the container `Exited` while its ports still appear bound. `podman start`
  works immediately after.
- `podman-compose` hangs on `depends_on: condition: service_healthy`. Start
  gluetun first, then qbittorrent.
- Bazarr rewrites `config.yaml` on shutdown and normalises inline lists to block
  style. Edit it stopped.
- qBittorrent's host-header validation is **off**. It compares the Host header's
  port against its own listening port, which can never match behind a reverse
  proxy or a remapped host port. Authentication is unaffected.
- gruff's address is DHCP. The TV uses `192.168.100.114:8096`; set a DHCP
  reservation before relying on it.
